# Vendor Damage Cost Forecasting and Safety Audit Reconciliation

> Portfolio replication of a data-engineering project from my Delta Air Lines work (Data Analytics Engineer / EHS & Risk Data Analyst).
> **All data in this repo is SYNTHETIC, anonymised sample data** — seeded and generated by `src/generate_synthetic_data.py`. It is **not** real Delta internal data, real vendor names, or real incident records. Vendors are anonymised as V-01…V-06. The synthetic dataset is calibrated to reproduce the *magnitude* of the original project's outcome (see Findings).

## What it does

A financial model linking **vendor safety audits, ramp incidents, and damage costs** to identify recurring losses by handling process — and to separate *reporting discrepancies* from *repeat operational issues*.

```
data/*.csv ──> src/ingest.py ──> PostgreSQL (or SQLite fallback)
                     │
                     ├─> src/cost_model.py   expected exposure = avg damage cost × incident frequency
                     ├─> src/reconcile.py    vendor submissions vs safety-leader audits
                     ├─> src/scorecards.py   vendor scorecards (cost, frequency, discrepancy rate)
                     └─> scripts/build_workbook.py ──> excel/*.xlsx
powerbi/ + tableau/ ──> dashboard definitions (DAX / calculated fields)
scripts/daily_contribution.py ──> daily synthetic batches (see below)
```

## Findings (synthetic replication, Jan–Jun 2025 sample period)

- **142 incidents, $73,903 total damage cost.**
- **Expected exposure (annualised) is highest for Ramp Loading ($54,202)** — 43 incidents × $630 avg — followed by Baggage Handling ($35,416). Fueling has the highest avg cost per incident ($792) but lower frequency, so lower total exposure. This is the core of the model: frequency matters as much as unit cost.
- **Preventable exposure: $8,945 (~$9,000).** Excess incidents above a 2-per-month baseline in recurring vendor+process groups, at a 25% achievable-reduction assumption. Concentrated in V-02 / Ramp Loading ($4,880) and V-01 / Baggage Handling ($3,192). In the original project, this analysis supported vendor corrective action that **helped avoid approximately $9,000 in losses** — that wording describes the original project's outcome, not a claim that these synthetic rows are real savings.
- **Audit reconciliation: 25 of 48 audits disagree (52.1% discrepancy rate)**, mostly underreporting by vendors (22). 10 audits flag a repeat operational issue. Underreporting is spread across vendors, but the *repeat* issues cluster in Ramp Loading / Baggage Handling — i.e. the same processes driving the cost exposure, not just paperwork gaps.
- **Vendor scorecards:** V-06 (Aircraft Cleaning) scores highest (87.4/100); V-02 (Ramp Loading) lowest (47.8/100) on cost + frequency + discrepancy rate.

## How to run

```bash
pip install -r requirements.txt
python -m src.run_pipeline        # generate data, load (SQLite fallback), model, reconcile, scorecards, workbook
# PostgreSQL instead:
DATABASE_URL=postgresql://user:pass@localhost:5432/vendor_damage python -m src.ingest
```

Outputs land in `analysis/` (`cost_model.json`, `exposure_by_process.csv`, `preventable_exposure.csv`, `reconciliation.json`, `vendor_scorecards.csv`, `vendor_damage.sqlite`) and `excel/Vendor_Damage_Cost_Forecasting.xlsx`.

## Stack

Python, SQL, PostgreSQL (SQLite fallback for local runs), Excel (openpyxl), Power BI (DAX in `powerbi/measures.dax`), Tableau (calculated fields in `tableau/README.md`), cost modeling, variance analysis, vendor scorecards, audit reconciliation, loss-prevention forecasting.

## Daily automation

`scripts/daily_contribution.py` — one run per day picks a random N (20–60) of small synthetic daily batches under `data/daily/YYYY-MM-DD/`, commits each separately, and pushes **once** at the end. It is idempotent per day and refuses to run with no git remote. See `CRON_SETUP.md` for the cron line (~09:00 America/Chicago). The cron is **not** created yet — the remote does not exist.
